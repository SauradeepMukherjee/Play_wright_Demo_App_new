## 2. Note on Discrepancy Test Cases

Five test cases (TC-SCRUM101-005, -013, -014, -027, -029) document confirmed differences between what the requirement document specifies and what the live SauceDemo application actually does, as found during the Playwright Test Planner's live exploration. Each of these test cases carries two distinct fields inside its Expected Result instead of one:

- **Expected (per requirement):** what the Requirement Analysis Report's FR/AC/BR says should happen.
- **Observed (live behavior):** what was actually confirmed by direct interaction with the live application.

These are intentionally **not** written as a single pass/fail assertion. They exist so that:
- The **Playwright Test Generator** can encode the *observed* behavior as the actual automated assertion (so the suite reflects reality and doesn't flap), while the *expected* behavior is preserved as a code comment / reference back to the requirement.
- The **Playwright Test Healer**, when one of these tests later "fails" against a fixed application, can correctly classify it as an **application issue** (the app changed to now match the requirement) rather than a script issue, and vice versa.
- Human reviewers and stakeholders (Open Questions in the RA report) have one place that shows requirement-vs-reality side by side for a go/no-go decision.
