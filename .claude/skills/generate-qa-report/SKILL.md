---
name: generate-qa-report
description: Regenerate the PDF and Excel QA reports from the latest test run and summarize where every report artifact lives. Use when asked to "generate the report", "regenerate reports", or "make the PDF/Excel report".
---

This repo's reporting is data-first (per [PROJECT_VISION.md](../../../PROJECT_VISION.md) guiding principle 4):
JSON results in `test-results/raw-results/*.json` are the source of truth, and every formatted report is a view
derived from that data — never hand-edit a report file directly.

Steps:

1. Confirm a test run has already happened (`test-results/raw-results/` is non-empty). If not, run
   `npm run test:e2e` first — the custom reporter (`scripts/execution-report-reporter.js` +
   `scripts/report-utils.js`, wired into `playwright.config.js`) writes the raw JSON and the HTML dashboard
   (`test-results/execution-report.html`) automatically as part of that run, no extra command needed.

2. Run `npm run report:pdf` (`scripts/generate-report.js`) to produce `test-results/execution-report.pdf`.

3. Run `npm run report:excel` (`scripts/generate-test-case-workbook.js`) to produce the Excel test-case workbook.

4. Report back the full set of artifact locations to the user:
   - `test-results/execution-report.html` — dashboard (pass/fail, browser breakdown, charts)
   - `test-results/execution-report.pdf`
   - `test-results/SCRUM-101-checkout-test-report.md` (or the equivalent per-story markdown report)
   - `test-results/results.json`, `test-results/results.xml` — raw JSON/JUnit
   - the Excel workbook path printed by `report:excel`

Known gap (see [ARCHITECTURE.md](../../../ARCHITECTURE.md) "Known coupling / gaps" and `ROADMAP.md` Phase 1): these
three report formats are generated by separate scripts rather than one unified command. Don't silently "fix" this
by merging scripts unless the user asks — it's tracked as deliberate future work, not an oversight to patch here.
